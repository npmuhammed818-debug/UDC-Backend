## Buyer-registration defects reproduced and fixed locally

1. Guided chat asked for a single field but sent even plain answers through paragraph AI extraction. Invalid responses or provider failures returned no fields, leaving the registration draft incomplete. The new `whatsapp-chat-ui.test.ts` regression failed before the fix with `full_name` undefined. Plain answers now use the active question and existing validation without a model call. Complex prose still uses paragraph extraction; this is not a replacement for AI comprehension. Additional outage regressions cover seller registration, two distinct offers retaining AED/MT, and agent registration retaining personal-email support.
2. The signed-webhook integration test exposed another failure: guidance keyword detection routed names containing `UDC` away from the active registration draft. Clear scalar or labelled answers now reach that draft first. Actual learning questions, multilingual language requests and multi-field prose retain their existing routing/extraction behavior.

The previous production incident's exact cause remains unconfirmed: Render logs, the deployed revision and Supabase records are unavailable here. These are reproduced code defects, not a claim that production is repaired.

## Reproduce the buyer regression

Use Node 24 and pnpm 11 with dependencies installed. Create a dedicated local database named `udc_qa_registration`; never substitute a production database. Apply the schema and run:

```sh
SUPABASE_DATABASE_URL='postgresql://udc_dev@127.0.0.1:5432/udc_qa_registration?sslmode=disable' \
SUPABASE_DIRECT_URL='postgresql://udc_dev@127.0.0.1:5432/udc_qa_registration?sslmode=disable' \
  pnpm --filter @workspace/db run push
UDC_QA_DATABASE_URL='postgresql://udc_dev@127.0.0.1:5432/udc_qa_registration?sslmode=disable' \
  node artifacts/api-server/test/integration/whatsapp-buyer-postgres.mjs
```

The runner rejects remote databases and names without the `udc_qa_` prefix. It creates uniquely labelled QA records in that database; repeated runs do not reuse customer identities. Outbound network interception rejects unexpected destinations. The passwordless connection and disabled TLS apply only to this local test database.

Worker checks used a separate Python 3.12 virtual environment, FastAPI 0.115.14, httpx 0.28.1, pytest 8.4.2, pandas 2.3.3, rapidfuzz 3.14.6, python-multipart, comtradeapicall 1.3.2 and requests. The initial minimal environment could run the 17 CI-selected tests, but full collection required the additional worker dependencies. No dependency declarations or lockfiles were changed.
