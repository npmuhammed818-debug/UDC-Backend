# Data retention and deletion procedure - draft for owner/legal review

This is an operational draft, not a claim that deletion or legal approval has happened.

- Inventory account/contact/company records, trade obligations, messages, document objects and extracted copies, optional memories, consent/security/audit records, provider copies and backups.
- Keep data only for an explained service, security, accounting, legal or dispute purpose. Do not invent a statutory period: the owner and lawyer must set category-specific periods before production.
- Optional memories have no automatic expiry today. Opt-out stops future learning; explain existing memory retention and verified deletion choices separately.
- A deletion request starts review, not automatic erasure. Verify identity proportionately. Establish legal holds and active trade obligations before removal.
- For each category record deletion evidence, or the specific lawful retention reason and expiry. Include signed URL expiry, object versions, extracted content, provider requests and backup expiry. Do not put private contents in the checklist or outcome.
- Backups must remain private and access-controlled. A restore must reapply deletion/tombstone records so erased accounts are not quietly resurrected. Full database and object-storage restore needs a rehearsal.
- Only close the request after the admin confirms each category and explains the outcome and retained categories to the requester. Checkboxes are human attestations, not technical proof that deletion took place.
- Legal holds or provider backup limits may delay full erasure. Tell the requester what remains and why. Never label review closure “all data deleted” without evidence.
