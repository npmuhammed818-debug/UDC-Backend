# Cargo-unit shipment tracking and ETA review — draft QA only

This feature builds on the milestone tracker in draft PR #130. It is **not deployed**; the migration is **not applied**. It does not add live carrier data feeds.

## Scope

A single shipment may contain multiple cargo units, including sea containers, air consignments and road loads. Each unit records:
- the transport mode, unit reference and internal status;
- mode-specific details: sea (vessel, voyage, bill of lading), air (flight, air waybill), road (vehicle reference);
- last UDC-recorded location/update and an estimated arrival.

Creating or updating cargo units is admin-only and recorded in the deal audit log. Mixed/contradictory transport references and duplicate unit references under the same shipment are rejected. No physical coordinates, shipment locations or customs movement are generated by an AI model.

An authorized buyer/seller can inspect the units through `GET /deals/:dealId/tracking` or WhatsApp's **My deals → Track shipment**. Assigned verified agents see only mode/status and ETA advisory, never container ID, carrier, vessel, flight, road vehicle, airwaybill or precise location. Membership/revocation checks are server-side.

## ETA interpretation

`etaAdvisory()` is a deterministic advisory based only on saved timestamps and saved unit status. When the ETA has passed but arrival is not recorded, it says **“Recorded ETA has passed; arrival is not confirmed.”** This is a follow-up task, not evidence of an actual delay. In-progress units whose last recorded report exceeds 48 hours can be labeled stale. Delivered/arrived/cancelled units have no overdue warning. There is no real-time GPS, AIS or carrier verification.

## Production rollout gates

- Review and apply `lib/db/migrations/20261024_shipment_cargo_units.sql` to **staging** first, after owner/DBA approval and backup plan. Keep RLS enabled and `anon`/`authenticated` privileges absent.
- Integrate this additive migration after PR #130 milestone migrations. Do not deploy app code expecting new tables before those tables exist.
- Validate with staging Meta/WhatsApp and test identities; confirm cargo references and notifications using real approved carrier/logistics evidence. Old number recovery from #129 remains a separate feature branch.
- Add a durable, idempotent ETA follow-up scheduler/outbox and delivery retries; advisory labels alone are not notifications.
- Test carrier references, mode validation, role redaction, revoked memberships, multiple consignments and reasonable load limits with authorized human reviewers.
- No production merge, environment variable changes or live SMS/email/WhatsApp messages without user approval.

The GitHub CI uses fictional fixture records and disposable local PostgreSQL. Passing those tests does not prove live provider integration, migrations or rollout readiness.
